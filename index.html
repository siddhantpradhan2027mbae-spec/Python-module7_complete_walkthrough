01

Reading & Writing Text Files

Why learn this

Everything your program does in memory vanishes the second it closes. A file is how it leaves something behind.

Problem it solves

Without a saved file, nobody, including you, can see what happened after the program's already finished running.

Where it's used

Every production pipeline writes a log file. This is the single most-used skill in this whole module.

Example 1 · FoundationalWriting and reading a log file, step by step
topic1_example1.py
log_messages = [
    "Pipeline started",
    "Connected to source database",
    "Validating 500 incoming rows",
]

with open("pipeline_log.txt", "w") as f:
    for i, message in enumerate(log_messages, start=1):
        line = f"Step {i}: {message}\n"
        f.write(line)
        print(f"[WRITING] -> {line.strip()}")   # watch each write happen live

with open("pipeline_log.txt", "r") as f:
    line_number = 0
    for line in f:
        line_number += 1
        print(f"[READING] line {line_number} | cursor at byte {f.tell()} | {line.strip()}")
Expected output
[WRITING] -> Step 1: Pipeline started
[WRITING] -> Step 2: Connected to source database
[WRITING] -> Step 3: Validating 500 incoming rows
[READING] line 1 | cursor at byte 25 | Step 1: Pipeline started
[READING] line 2 | cursor at byte 62 | Step 2: Connected to source database
[READING] line 3 | cursor at byte 100 | Step 3: Validating 500 incoming rows
Example 2 · Enterprise shapeA reusable logger function, with validation built in
topic1_example2.py
def log_event(message, level="INFO", filename="pipeline_log.txt"):
    try:
        with open(filename, "a") as f:   # append, never erase history
            entry = f"[{level}] {message}\n"
            f.write(entry)
        print(f"Logged -> {entry.strip()}")
    except Exception as e:
        print(f"Could not write to log file: {e}")

log_event("Batch job triggered")
rows_processed, expected_rows = 480, 500

if rows_processed < expected_rows:
    log_event(f"Only {rows_processed}/{expected_rows} rows processed", level="WARNING")
else:
    log_event("All rows processed successfully")
🎤 Interview angle

"Why wrap file writing in a function instead of calling open() everywhere?" Because one function means one place to fix formatting, add retries, or change behaviour later, not fifty scattered copies.

02

seek(), tell(), close()

Why learn this

Sometimes you need to control exactly where inside a file you're reading from, not just "the next line."

Problem it solves

Re-reading an entire huge file just to get back to a spot you already visited wastes time. seek() jumps straight there.

Where it's used

Log-monitoring tools, checking a file's size without opening the whole thing, resuming a partially read file.

Example 1 · FoundationalWatching the cursor move, one call at a time
topic2_example1.py
with open("pipeline_log.txt", "r") as f:
    print(f"Start: cursor at byte {f.tell()}")
    first_line = f.readline()
    print(f"After line 1: cursor at byte {f.tell()} | {first_line.strip()}")
    second_line = f.readline()
    print(f"After line 2: cursor at byte {f.tell()} | {second_line.strip()}")
    f.seek(0)
    print(f"After seek(0): cursor back at byte {f.tell()}")
    print(f"Re-reading line 1: {f.readline().strip()}")
Expected output
Start: cursor at byte 0
After line 1: cursor at byte 25 | Step 1: Pipeline started
After line 2: cursor at byte 62 | Step 2: Connected to source database
After seek(0): cursor back at byte 0
Re-reading line 1: Step 1: Pipeline started
Example 2 · Enterprise shapeChecking file size before processing it
topic2_example2.py
def get_file_size(filename):
    with open(filename, "rb") as f:
        f.seek(0, 2)       # jump straight to the end
        size = f.tell()      # that position IS the file size
    return size

size = get_file_size("pipeline_log.txt")
print(f"pipeline_log.txt is {size} bytes")

if size == 0:
    print("WARNING: log file is empty, something may have failed silently")
else:
    print("Log file has content, safe to continue")
03

Working with CSV Files

Why learn this

CSV is the single most common format raw data actually arrives in, from clients, branches, exports.

Problem it solves

Splitting text on commas by hand breaks the moment a value itself contains a comma. The csv module handles that correctly.

Where it's used

Every spreadsheet export, every simple handoff between two systems that don't share a database.

Example 1 · FoundationalCreating, writing, and reading a CSV, step by step
topic3_example1.py
import csv

# we build our OWN dummy data here - nothing external to go missing
transactions = [
    ["txn_id", "customer", "amount"],
    ["T001", "Aravind Sharma", "4599"],
    ["T002", "Priya Nair", "12300"],
    ["T003", "Rohit Verma", "800"],
]

with open("transactions.csv", "w", newline="") as f:
    writer = csv.writer(f)
    for row in transactions:
        writer.writerow(row)
        print(f"[WRITING ROW] {row}")

with open("transactions.csv", "r") as f:
    reader = csv.reader(f)
    header = next(reader)   # next() grabs just one row - here, the header
    print(f"Header row: {header}")
    for row_number, row in enumerate(reader, start=1):
        print(f"[READING] data row {row_number}: {row}")
Expected output
[WRITING ROW] ['txn_id', 'customer', 'amount']
[WRITING ROW] ['T001', 'Aravind Sharma', '4599']
[WRITING ROW] ['T002', 'Priya Nair', '12300']
[WRITING ROW] ['T003', 'Rohit Verma', '800']
Header row: ['txn_id', 'customer', 'amount']
[READING] data row 1: ['T001', 'Aravind Sharma', '4599']
[READING] data row 2: ['T002', 'Priya Nair', '12300']
[READING] data row 3: ['T003', 'Rohit Verma', '800']
Example 2 · Enterprise shapeFiltering high-value transactions
topic3_example2.py
def load_high_value_transactions(filename, threshold=1000):
    high_value = []
    with open(filename, "r") as f:
        reader = csv.DictReader(f)
        for row in reader:
            amount = int(row["amount"])   # CSV values arrive as text, cast first
            print(f"Checking {row['customer']}: amount = {amount}")
            if amount > threshold:
                high_value.append(row)
                print("  -> above threshold, keeping")
            else:
                print("  -> below threshold, skipping")
    return high_value

result = load_high_value_transactions("transactions.csv", threshold=1000)
print(f"{len(result)} high-value transaction(s) found")
🎤 Interview angle

"Why DictReader instead of plain csv.reader here?" Because row["amount"] keeps working even if a branch office reorders their export columns tomorrow. row[2] breaks silently the moment it does.

04

Introduction to JSON

Why learn this

JSON is the universal format config files and APIs speak, across every language, not just Python.

Problem it solves

Teams need a format that's readable by humans AND easy for a program to parse. JSON is the industry's answer.

Where it's used

Pipeline config files, and the response body of basically every REST API you'll ever call.

Example 1 · FoundationalA dictionary becoming JSON text
topic4_example1.py
import json

pipeline_config = {
    "pipeline_name": "daily_settlement",
    "batch_size": 500,
    "retry": True,
    "sources": ["branch_pune", "branch_mumbai"],
}

print("Right now this is a dictionary:", type(pipeline_config))

json_text = json.dumps(pipeline_config, indent=4)
print("After json.dumps(), it's TEXT:", type(json_text))
print(json_text)
Example 2 · Enterprise shapeValidating a config before trusting it
topic4_example2.py
class MissingConfigKeyError(Exception):
    pass

def validate_config(config, required_keys):
    for key in required_keys:
        print(f"Checking for '{key}'...")
        if key not in config:
            raise MissingConfigKeyError(f"Config is missing required key: '{key}'")
    print("Config validated successfully")

required = ["pipeline_name", "batch_size", "retry", "destination"]

try:
    validate_config(pipeline_config, required)
except MissingConfigKeyError as e:
    print(f"Cannot start pipeline: {e}")
05

Working with JSON Data

Why learn this

Topic 4 made JSON text. Real pipelines need that text to live on disk, and load back as real data later.

Problem it solves

A script restarting shouldn't lose its settings. Save once, load every single time it runs again.

Where it's used

Any pipeline that reads its own settings instead of hardcoding values straight into the script.

Example 1 · FoundationalSaving and loading a config file, step by step
topic5_example1.py
config_to_save = {"pipeline_name": "daily_settlement", "batch_size": 500, "retry": True}

with open("pipeline_config.json", "w") as f:
    json.dump(config_to_save, f, indent=4)
    print("Saved config to pipeline_config.json")

with open("pipeline_config.json", "r") as f:
    loaded = json.load(f)
    print(f"Loaded back: {loaded}")
    print(f"Type: {type(loaded)}")
    print(f"batch_size specifically: {loaded['batch_size']}")
Example 2 · Enterprise shapeLoading settings with a safe fallback
topic5_example2.py
def load_pipeline_settings(filename, defaults):
    try:
        with open(filename, "r") as f:
            settings = json.load(f)
        print(f"Loaded settings from {filename}")
    except FileNotFoundError:
        print(f"{filename} not found, using defaults")
        settings = defaults

    batch_size = settings.get("batch_size", 100)
    retry = settings.get("retry", False)
    print(f"Running with batch_size={batch_size}, retry={retry}")
    return settings

defaults = {"batch_size": 100, "retry": False}
load_pipeline_settings("pipeline_config.json", defaults)   # exists
load_pipeline_settings("missing_config.json", defaults)    # doesn't, triggers fallback
06

OS Module

Why learn this

A script needs to know what's actually sitting on disk, not just assume.

Problem it solves

Opening or deleting a file that isn't there crashes your program. Checking first avoids that completely.

Where it's used

Renaming a processed file, cleaning up temporary files, confirming a job actually produced output.

Example 1 · FoundationalChecking, renaming, and listing files
topic6_example1.py
import os

print("Current folder:", os.getcwd())
print("Files here right now:", os.listdir("."))

if os.path.exists("transactions.csv"):
    print("transactions.csv found, safe to rename")
    os.rename("transactions.csv", "transactions_2026_01_15.csv")
    print("Renamed. Files now:", os.listdir("."))
else:
    print("transactions.csv not found, nothing to rename")
Example 2 · Enterprise shapeCleaning up temporary files
topic6_example2.py
def cleanup_temp_files(folder, prefix="temp_"):
    removed_count = 0
    for filename in os.listdir(folder):
        if filename.startswith(prefix):
            os.remove(os.path.join(folder, filename))
            removed_count += 1
            print(f"Removed: {filename}")
    print(f"Cleanup complete, {removed_count} file(s) removed")

# create dummy temp files first, so this example is self-contained
for name in ["temp_cache1.txt", "temp_cache2.txt"]:
    with open(name, "w") as f:
        f.write("temporary data")

cleanup_temp_files(".", prefix="temp_")
The one rule that prevents a bad day: never call os.remove() without an os.path.exists() check first, or a condition like startswith() narrowing exactly what gets deleted.
07

pathlib

Why learn this

Windows uses backslashes in paths. Mac and Linux use forward slashes. Code shouldn't care which one it's on.

Problem it solves

pathlib handles that OS difference automatically, and gives a real object instead of a string to slice by hand.

Where it's used

Nearly all modern production Python code has already moved to pathlib over the older os.path style.

Example 1 · FoundationalBuilding and inspecting a path
topic7_example1.py
from pathlib import Path

file_path = Path("data") / "incoming" / "transactions_2026_01_15.csv"
print("Full path:", file_path)
print("File name:", file_path.name)
print("Extension:", file_path.suffix)
print("Parent folder:", file_path.parent)
print("Does it exist?", file_path.exists())
Example 2 · Enterprise shapeCreating a folder and finding files inside it
topic7_example2.py
output_folder = Path("data") / "processed"
output_folder.mkdir(parents=True, exist_ok=True)
print(f"Folder ready: {output_folder}")

for csv_file in Path(".").glob("*.csv"):
    print(f"Found CSV file: {csv_file.name}")
08

Compressed File Handling

Why learn this

Once a day's files are done being actively used, they still need to be kept, just smaller and bundled together.

Problem it solves

Raw files pile up fast. Compression keeps months of history without quietly eating the whole disk.

Where it's used

End-of-day archiving, and long-term retention of log files specifically.

Example 1 · FoundationalCreating a zip archive and inspecting it
topic8_example1.py
import zipfile

with zipfile.ZipFile("daily_archive.zip", "w") as zipf:
    zipf.write("pipeline_log.txt")
    print("Added pipeline_log.txt to the archive")

with zipfile.ZipFile("daily_archive.zip", "r") as zipf:
    print("Contents right now:", zipf.namelist())
Example 2 · Enterprise shapeA full end-of-day archive function
topic8_example2.py
import gzip, shutil

def archive_day(date_str, files_to_archive):
    zip_name = f"settlement_{date_str}.zip"
    with zipfile.ZipFile(zip_name, "w") as zipf:
        for file in files_to_archive:
            zipf.write(file)
            print(f"Archived: {file}")
    print(f"Created {zip_name}")

archive_day("2026_01_15", ["pipeline_log.txt", "pipeline_config.json"])

# logs compress best on their own with gzip, separate from the zip
with open("pipeline_log.txt", "rb") as f_in:
    with gzip.open("pipeline_log.txt.gz", "wb") as f_out:
        shutil.copyfileobj(f_in, f_out)
print("Log additionally compressed as pipeline_log.txt.gz")
